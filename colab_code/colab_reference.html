Google Colab — quick reference

The four things you'll need every time you fine-tune on Colab and bring the result back into the Import-adapter tab: download output files, upload inputs, change the GPU, and check live resource usage. Each tab below shows the exact Colab UI element to click (highlighted in red) — plus the equivalent code if you'd rather automate.

Download a file from Colab Right-click any file in the Files panel — works for the LoRA adapter folder you'll drop into the Import-adapter tab.

The UI way (no code)

⚠️
For a folder, right-click won't work directly — zip it first (see the code path below) or push to Drive.

The code way

Useful at the end of a training cell so the download starts automatically.

from google.colab import files
files.download("/content/adapter_model.safetensors")    # one file

# Whole adapter folder → zip first
import shutil
shutil.make_archive("/content/adapter", "zip", "/content/finetune_out/adapter")
files.download("/content/adapter.zip")

For files > ~100 MB: push to Drive

Same Files panel — click the Mount Drive icon (the third toolbar button, the folder-with-Drive-logo). Or run:

from google.colab import drive
drive.mount("/content/drive")
import shutil
shutil.copytree(
    "/content/finetune_out/adapter",
    "/content/drive/MyDrive/finetune_adapters/qwen-0.5b-20260522",
)

Then on your laptop, open drive.google.com → right-click the folder → Download. Drive zips it server-side.

💡
For this project, the folder you want is the one containing adapter_config.json + adapter_model.safetensors. Once it's on your laptop, paste the absolute path into Tab 4 — Import adapter.

Upload a file to Colab Same Files panel, the toolbar button on the left.

The UI way

⚠️
/content/ is ephemeral — it disappears when the runtime recycles (~12 h idle, or when you change runtime type). For anything you need long-term, mount Drive (next section).

The code way

from google.colab import files
uploaded = files.upload()           # opens an OS file picker
for name, data in uploaded.items():
    print(name, len(data), "bytes") # files now live in the CWD

For persistent / large files: mount Drive

In the same Files-panel toolbar, click the Mount Drive icon (third toolbar button — looks like a folder + Drive logo). Or use code:

from google.colab import drive
drive.mount("/content/drive")
# Files are now at /content/drive/MyDrive/...

Step 3: nvidia-smi for the detail

!nvidia-smi --query-gpu=memory.used,memory.total,utilization.gpu \

utilization.gpu tells you if training is GPU-bound. Single-digit % usually means a data-loading bottleneck, not compute.

From inside PyTorch (during training)

import torch
def show_vram(tag=""):
    a = torch.cuda.memory_allocated() / 1e9
    r = torch.cuda.memory_reserved()  / 1e9
    print(f"[{tag}] allocated={a:.2f} GB  reserved={r:.2f} GB")

show_vram("before")
# ... training step ...
show_vram("after")

One-cell snapshot — CPU + GPU + Disk together

import torch, psutil, shutil
if torch.cuda.is_available():
    p = torch.cuda.get_device_properties(0)
    used = torch.cuda.memory_allocated() / 1e9
    print(f"GPU  {p.name}: {used:.2f} / {p.total_memory/1e9:.1f} GB")
m = psutil.virtual_memory()
print(f"RAM            : {(m.total-m.available)/1e9:.2f} / {m.total/1e9:.1f} GB")
du, df_, _ = shutil.disk_usage("/content")
print(f"Disk /content  : {(du-df_)/1e9:.1f} / {du/1e9:.1f} GB")
💡
If memory_allocated climbs across epochs, something is holding tensor references (lists growing without bound). Wrap eval blocks in with torch.no_grad(): and call torch.cuda.empty_cache() between epochs.
