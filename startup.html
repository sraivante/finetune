Quick Start Guide

Ollama Fine-Tune Studio

Fine-tune any Ollama model on your own documents — LoRA train, merge to GGUF, register with Ollama, evaluate, and chat. Follow the colored steps below.

1. Check prerequisites 2. One-time install 3. Start Ollama 4. Launch the app 5. Use the 6 tabs 6. Stop the app Troubleshooting
1

Check prerequisites

Confirm these are installed before continuing. Each card has the verify command.

  • Py

    Python 3.10+

    Runs the Streamlit app and training stack. Verify with python --version

  • Ol

    Ollama (running)

    Source models and final inference. Verify with ollama list

  • Git

    Git

    One-shot clone of llama.cpp for GGUF conversion. Verify with git --version

  • 💾

    ~15 GB free disk

    Model downloads, checkpoints, merged weights, and GGUF files.

  • 🧠

    8 GB RAM minimum

    Loading and training a 0.5B–1.1B model on CPU.

  • ⚡

    NVIDIA GPU (optional)

    Required for 3B+ models. Verify with nvidia-smi

2

One-time install

Creates the virtual environment, installs dependencies, and shallow-clones llama.cpp for GGUF conversion.

Windows (recommended): from a terminal in the project folder, run:

setup.bat

Manual (any OS):

python -m venv .venv
.venv\Scripts\activate          # or: source .venv/bin/activate
pip install -r requirements.txt
git clone --depth 1 https://github.com/ggerganov/llama.cpp llama.cpp
pip install -r llama.cpp/requirements.txt

Pull at least one Ollama model (skip if you already have one):

ollama pull qwen2.5:0.5b-instruct     # smallest, CPU-friendly default
3

Start Ollama

The app talks to Ollama on localhost:11434. Skip this step if Ollama is already running as a Windows service.

ollama serve

You should see "Listening on 127.0.0.1:11434". Leave this terminal window open and continue in a new one.

4

Launch the app

One command — opens the Streamlit UI at http://localhost:8501.

Windows:

run.bat

Manual / any OS:

.venv\Scripts\activate           # or: source .venv/bin/activate
streamlit run app.py

Your browser opens automatically. If not, navigate to http://localhost:8501.

5

Use the 6 tabs

Built to be used left-to-right, but you can jump straight to Import adapter if you already have a fine-tuned folder, or to Evaluate to test any existing Ollama model.

Tab 1

⚙️ Configure

Upload PDF / DOCX / TXT / MD / CSV / JSON / PY documents and set hyperparameters. Every option has a recommended default.

Tab 2

🧱 Dataset

Generate Q&A pairs from your docs (or upload your own JSONL), merge multiple files, edit rows inline, and approve the result.

Tab 3

🚀 Fine-tune

LoRA train → merge → convert to GGUF → register with Ollama. Live loss curve and progress log. Outputs a new ollama list tag.

Tab 4

📦 Import adapter

Already trained elsewhere (e.g. Colab)? Point at the folder and we merge → GGUF → register. Accepts both LoRA adapters and merged HF models.

Tab 5

📊 Evaluate

Pick a model, pick a JSONL test file. Live pass / fail counters, abort button, and a downloadable HTML report with collapsible per-row details.

Tab 6

💬 Chat & validate

Chat with the fine-tuned (or any) Ollama model. Delete unwanted models from the inline manager.

6

Stop the app

The right way depends on whether you still have the terminal open.

🖥️ Have the terminal?

Click into the window running Streamlit and press Ctrl + C. It exits cleanly.

🪟 Closed the terminal?

From any new terminal:

taskkill /F /IM streamlit.exe

🐧 macOS / Linux

Use pkill:

pkill -f streamlit

🦙 Stop Ollama too?

If you started ollama serve in a terminal, Ctrl+C it. If it's a Windows service, it keeps running — that's fine.

Common gotchas

The full list lives in usage.html §15 — these are the ones almost everyone hits.

"Ollama unreachable" in the sidebar

ollama serve isn't running. Open a separate terminal and run it (Step 3). Or, on Windows, the Ollama service may have stopped — check it under Services → Ollama Service.

"No HF mapping for <model>"

The Ollama tag you picked isn't in OLLAMA_TO_HF in config.py. Add one line, e.g. "my-model:tag": "huggingface-user/MyModel-Instruct", and restart the app. LoRA needs the original HF weights — Ollama only ships GGUF.

"Got 0 pairs from N chunks" during dataset generation

The generation model is producing broken JSON. On the Dataset tab, switch Generation model to a stronger one (qwen3:14b or qwen2.5-coder:14b). Tiny 0.5B models are unreliable at structured output.

Out of memory during training

On the Configure tab, lower in this order: batch size → max_seq_length → switch to a smaller base model. Increase gradient_accumulation_steps to keep the effective batch the same.

Import adapter says "Could not detect folder kind"

You probably pointed at the wrong directory. Look one level deeper for the actual checkpoint folder (e.g. checkpoint-1374/ or <output_dir>/adapter/) — the one that contains adapter_config.json directly.

Evaluate accuracy is far below 100% on examples it was trained on

The most common causes (in order): the LoRA's target_modules default is too narrow (q_proj+v_proj only — add k_proj, o_proj, gate_proj, up_proj, down_proj); too few epochs with constant LR (try 8–12 epochs with cosine); class imbalance in the training data; too few examples per output for high-cardinality tasks.
